## Issues & rekomendasi
1. **[HIGH] APK di ambang 4 GiB (F1).** Pilih salah satu (Lead/owner, revisi ADR 0004 §6):
   - (a) workflow drms: `-Xmx1536m -XX:MaxMetaspaceSize=384m` dan `org.gradle.workers.max=1` untuk job APK self-hosted (target puncak
     anon ≤ 3,2 GiB); atau
   - (b) runner: `CI_MEMORY` 4g → **5g** (dengan `--memory-swap` sama). Data R10: MemAvailable host min 7,1 GiB saat APK, swap datar →
     5 GiB masih menyisakan ±6 GiB. Pemicu evaluasi §6 butir 3 tetap berlaku.
   Rekomendasi QA: (a) dulu (tanpa perubahan kapasitas), lalu ulangi build APK dingin (cache Gradle kosong) sebagai uji.
2. **[HIGH] GHCR push-by-digest tidak jalan dengan buildx `driver: docker` (F2).** Perbaikan di workflow drms (sesi app): untuk
   `publish == 'true'` pakai driver `docker-container` (buildkit dalam dockerd sysbox), opsional cache `type=local` di `/cache`; driver
   `docker` hanya untuk build lokal/PR. Revisi plan 12 R8 (asumsi "docker driver + containerd store mendukung push-by-digest" salah).
   Setelah fix: jalankan push `develop` lagi dan verifikasi digest + attestations SBOM/provenance (`docker buildx imagetools inspect
   …@sha256 --format '{{json .Provenance}}'`). Driver `docker-container` di dalam sysbox **[UNVERIFIED]**.
3. **[MEDIUM] `disk.img` sparse → `/srv/ci` bukan alokasi tetap.** `stat`: size 42 949 672 960, blok 49 157 352 × 512 = 25,2 GB;
   `mkfs.ext4` men-discard (default) sehingga hasil `fallocate` hilang; loop0 mendukung discard (`discard_max_bytes` 4 GiB) dan
   `fstrim.timer` enabled → akan dikosongkan lagi tiap minggu. `/` naik 119,3 → 137,8 GB (69 %) selama R10. Opsi: (i) role `ci_runner`
   `mkfs.ext4 -E nodiscard` + `fallocate -l 40G` ulang (mengisi hole tanpa hapus data, saat runner idle) + kecualikan `/srv/ci` dari fstrim;
   atau (ii) terima sparse dan hitung 40 GiB penuh di ambang `/` (alert 70 % akan aktif ±sekarang). Plan §6 "alokasi tetap" perlu dikoreksi.
4. **[LOW] Pertumbuhan cache cepat:** `/srv/ci` 4,7 → 20,1 GiB dalam 2 run (Flutter/Gradle/pub + build cache 7,9 GB). Pantau
   `ci-runner-gc.timer` 7 hari; alert 85 % sudah ada.
5. **[LOW] Metrik job gagal tidak akurat:** container selalu keluar `rc=0` (runner listener exit 0 walau job Failed) → `JOBS_FAIL`
   supervisor tidak menghitung job gagal. Bila perlu, parse `completed with result:` dari log atau terima sebagai metrik "container".
6. **[INFO] IO:** iowait host sampai 64 % saat APK meski `io.max` 60/120 MB/s di loop0+sda; dampak latensi prod tetap < 2×.
   Atribusi io.max loop→sda tetap OPEN (tidak diukur per device).
