## 5. RISIKO
| # | Risiko | Dampak | Bukti | Mitigasi usulan |
|---|---|---|---|---|
| R1 | **SSH root + password auth terbuka ke internet tanpa firewall/fail2ban** | Kompromi host total via brute force | `sshd -T`: permitrootlogin yes, passwordauthentication yes, port 22; ufw inactive; iptables ACCEPT; fail2ban tidak ada | Prioritas #1 FASE 2: user admin key-only, matikan password & root login, ufw, fail2ban. Perhatikan urutan agar tidak terkunci (lihat R6) |
| R2 | **Tanpa swap, RAM 15,6 GiB = batas minimum** | OOM kill Postgres/Odoo saat lonjakan; hanya muat 1–2 client + staging terbatas | `free -h`, estimasi §2 | Swap 4 GB (§4.6), `mem_limit` ketat, ukur `docker stats` setiap bring-up; rencana upgrade ke 8 vCPU/32 GB atau pindah mail/observability ke VPS-2 |
| R3 | **Kernel baru belum aktif (reboot required)** | Patch keamanan kernel/libc belum berlaku | `/var/run/reboot-required` (+ linux-image-6.8.0-142, libc6) | Jadwalkan reboot terkontrol oleh user sebelum bootstrap (butuh akses console panel jika gagal boot) |
| R4 | Reputasi mail: PTR default `hstgr.cloud`, IP di range hosting | Email ditolak/masuk spam | `dig -x` | Set PTR v4 **dan** v6 → `mail.<domain>`, atau nonaktifkan IPv6 untuk SMTP keluar bila PTR v6 tak bisa diset |
| R5 | Docker mem-bypass ufw | Port container ter-expose publik meski ufw deny | CLAUDE.md §3.6/§4.4 (belum terjadi: Docker belum ada) | Hanya Traefik & mail publish port; verifikasi `ss -tlnp` + scan eksternal di QA |
